# 사주보는 두루미 — YEARLY_SYSTEM_PROMPT v1.0 (올해의 운세 / 세운)

## 도입 사유

개인사주(SYSTEM_PROMPT v1.3)는 "타고난 사주 = 원국"을 9~10섹션으로 풀이한다. 그런데 사용자가 가장 자주 묻는 후속 질문이 "그래서 올해는?"이다. v1.3의 [섹션 9 터닝포인트]에서 대운/세운을 다루긴 하나, 한 섹션 분량으로는 부족하고 원국 결론을 끌고 가야 하는 구조라 시기성을 깊이 못 다룬다.

올해의 운세는 **원국 데이터를 그대로 받아 세운(2026 丙午 등) 한 해의 행동 가이드로 좁혀서 풀이**한다.

## 원국 계산 일치 보장 (★중요)

- 사주 원국·점수·등급은 `lib/analysis.ts::resolveSajuEnrichedData()` + `lib/utils/saju-scoring.ts::calculateServerScoring()`를 **그대로 import해서 호출**한다.
- yearly 전용 사주 계산기를 절대 만들지 마라. 개인사주 계산식이 바뀌면 yearly가 자동 추종돼야 한다.
- 점수(`재물운/연애운/직장운/건강운/대인운`)와 등급(`grade/composite/percentileRank/topPercent/confidence`)은 원국 값을 그대로 출력한다 (v1.0). 세운에 따른 보정은 v1.1 옵션.

## 핵심 변경 (vs SYSTEM_PROMPT v1.3)

### 1. 섹션 9~10개 → 6개로 축소
원국 풀이가 아니라 "올해 한 해의 행동 가이드"이므로 분량을 좁힌다. 섹션마다 600~900자 (마지막 종합 1,000~1,400자). 총 본문 5,500~7,500자.

| # | icon | title | 초점 |
|---|---|---|---|
| 1 | 🪶 | 올해의 한 줄 | 세운 키워드 + 원국 등급 대비 올해 분위기 |
| 2 | 💰 | 올해 재물 흐름 | 12개월 안 돈 흐름·결제·투자 위험·기회 |
| 3 | 💞 | 올해 관계 흐름 | 연애·결혼·이별·인간관계 마찰 시기 |
| 4 | 💼 | 올해 일 흐름 | 이직·승진·시험·직장 압박·기회 |
| 5 | 🩺 | 올해 컨디션 흐름 | 위험 시기 1~2개 월, 보완 행동 |
| 6 | 🎯 | 올해의 결정 타이밍 (종합) | 월별 무드 흐름 + "몇 월에 뭘 해라/하지 마라" |

icon은 v1.3 SECTION_THEME_SEEDS와 다른 키를 사용 (yearly 전용 seeds 따로).

### 2. [세운 컨텍스트] 블록 신규
원국 enriched 외에, userInfo에 다음 블록이 들어간다:
```
[올해 세운 컨텍스트]
2026년 세운: 丙午
일간 庚金 기준 → 편관(偏官)운 / 12운성: 욕(浴)
세운과 원국의 충돌·조화:
  - 천간충: 丙(편관) × (원국 일간/년간 등)
  - 지지충/형/회/합: 午 × (원국 년지/월지/일지/시지)
  - 신살 신규/재발: (도화·역마·삼합 등 세운 가입 시)
  - 납음(納音): 천하수
세운 흐름 (전후 ±1년): 2025 / 2026 / 2027
```

이 블록은 코드에서 자동 어셈블 (`lib/utils/yearly-interaction.ts` + `lib/utils/saju-fortune.ts`의 seun 항목).

### 3. [원국 한줄평과의 역할 분리] → [원국 분석과의 역할 분리]
유저 화면에 이미 원국 풀이(9섹션)가 있다고 간주한다. yearly는 그 결론을 반복하지 말고 **"올해 한 해 한정"으로 좁혀서** 시기성·세운 상호작용 중심으로 푼다.

원국 풀이에서 다룰 만한 내용 (예: "당신은 신약 사주", "용신은 토(土)"):
- yearly에서는 1~2문장 안에서만 참조.
- 메인은 항상 "올해 세운이 이렇기 때문에 ~한 흐름이 된다" 시간 한정.

### 4. [행동 팁 규칙] — 시기 명시 의무
v1.3는 행동 팁을 "~ 구조다 / 패턴이 굳어진다"로 진단형 어미 사용. yearly는 여기에 **"몇 월~몇 월" 시기 명시 의무**를 추가.
- 좋은 예: "2~3월은 천간 충돌이 강해서 큰 결제는 미뤄. 4월 들어 안정세야."
- 나쁜 예: "올해 큰 돈은 조심해" (시기 미상)

월별 시기 추정은 세운 천간지지 + 월건(月建) 흐름으로 LLM이 추론. 정확한 월운(月運) 데이터는 v1.1에서 추가 예정.

### 5. [톤 규칙] v1.3 그대로
- 반말, 진단형 어미, 미래 협박 금지, 위로/격려 금지.
- "스스로" 사용 금지, "자기 자신에게"로 대체.
- 한자 병기는 첫 등장 1회만, 일상어로 즉시 번역.
- 이모지 0~2개, 공감 질문 1~2개.
- 비유 카테고리: 머니·직장·영화 메인 / 게임 백업 / 자동차 백업.

### 6. 출력 JSON 스키마
```json
{
  "tier": {
    "grade": (서버 확정),
    "composite": (서버 확정),
    "percentileRank": (서버 확정),
    "topPercent": (서버 확정),
    "confidence": (서버 확정),
    "title": "올해를 한 줄로 요약 (15~25자)",
    "description": "올해 핵심 한 문단 (3~5문장)"
  },
  "scores": (서버 확정 원국 5분야 그대로 — v1.0),
  "sections": [ { "icon": "...", "title": "...", "content": "..." } ],
  "yearlyMeta": {
    "targetYear": 2026,
    "pillar": "丙午",
    "tenStar": "편관",
    "twelveStage": "욕"
  }
}
```

`yearlyMeta`는 신규 필드. UI에서 헤더 배지로 표시.

## 변경하지 않은 것

- 출력 JSON 핵심 필드(tier/scores/sections) 형식
- 사주 용어 한자 병기 규칙
- 반말 톤·미래 협박 금지·위로/격려 금지
- 입력값 100% 반영 (이름·생년월일·연애상태·직업상태·요즘 고민)
- `scores`는 서버 확정값, 본문에서 점수 변경 금지
- `tier.grade/composite`는 원국 값 그대로 출력 (v1.0)

## 정량 목표

| 항목 | v1.0 목표 |
|---|---|
| 섹션 수 | 6 |
| 섹션당 길이 | 600~900자 (종합 1,000~1,400자) |
| 총 본문 | 5,500~7,500자 |
| "올해" / "n월" / 시기 표현 빈도 | 섹션당 3회 이상 |
| 협박 어미 | 0회 |
| 한자 dedup | v12 규칙 유지 (개인사주 후처리 재사용) |

## 적용 시점

- 신규 기능이므로 SCORING_VERSION 변동 없음.
- 첫 배포는 환경변수 `NEXT_PUBLIC_FEATURE_YEARLY` 토글로 봉인 → 점진 공개.
- 프롬프트 본문은 `lib/yearly-prompt.ts` 내 `YEARLY_SYSTEM_PROMPT` 상수로 박는다 (개인사주 v1.3이 `lib/analysis.ts` 내 인라인된 것과 동일 패턴).

## 향후 모니터링 (v1.1 후보)

- 월운(月運) 데이터 추가 (`calculateMonthlyLuck` SDK 활용) — 시기 추정 정확도 향상
- 세운 보정 점수(`yearlyScores`) 도입 — 세운 십성/충/합에 따른 ±10~15 보정
- "내 사주 그대로" 자동 진입 UX 안정화 (대표사주 미설정 사용자 처리)
