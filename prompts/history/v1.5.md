# 사주보는 두루미 — SYSTEM_PROMPT (RESULT) v1.5

## 변경 사유 (vs v1.4)
v1.4 배포 후 9건 실측: 게임 슬랭 0·반말·위트는 잘 나오나, 규칙을 모델이 ~75%만 따름 →
1. **상위권(내부 S·A) 약점 누출** — 4건 중 3건이 "상사 복만 빼면"·"관리는 가성비"·"밥상 엎는" 등 약점 절 삽입(규칙=약점0).
2. **맞춤형 오류** — 박소연: 재물 최고점인데 title은 "파산 직전"(최고를 약점으로).
3. **다양성 부족** — 재물 최고 2명이 둘 다 "돈 냄새는 기막힌데…"로 수렴.

원인: "프롬프트 규칙 추가"는 확률적 모델에 약발 한계. → **틀리기 쉬운 판단(분야 선택·등급 게이팅)을 서버 코드가 결정론적으로 계산해 주입**하는 구조로 전환.

## 핵심 변경 — 서버 계산 scaffold (lib/analysis.ts, 프롬프트 텍스트 아님)
runFullAnalysis에서 서버 확정 점수로 per-result 지침을 계산해 userInfo [서버 계산 결과] 블록에 주입:
- **buildTitleDirective()**: 5분야 점수에서 최고/최저 분야를 코드로 산출(동점 시 고정 우선순위) + 세계 매핑(재물→돈/직업→회사/애정→연애/건강→몸/대인→사람).
  - **맞춤형 결정론화**: "강점=최고 분야에서만, 약점=최저 분야에서만. 최고를 약점으로 쓰면 실패." → 박소연식 오류 차단.
  - **등급밴드 게이팅(per-result)**: 내부 S·A=약점 절 금지(강점만)/B=강점 우세+애교흠/C=반반/D=팩폭. 일반 규칙보다 강하게 이 사람용으로 못박음.
  - **상태 가드**: 솔로→연애 세계 금지, 학생/취준→회사 세계 금지 자동 주입(기존 규칙과 정합).
  - **다양성 넛지**: "흔한 표현('돈 냄새') 반복 말고 다른 각도로."
- **logTitleQuality()**: 파싱 후 게임 슬랭 / 상위권 대비구조 검출 시 `[TITLE_QC]` console.warn. **재생성 안 함(관찰만)** — 현재 품질이 재생성까진 불필요하다는 운영자 판단.
