# 반려동물 궁합 — 종(species) 어휘 혼입 버그 수정 계획

날짜: 2026-07-13
대상: `lib/pet-compat.ts` (인라인 const `PET_COMPAT_SYSTEM_PROMPT` + `buildPetCompatUserInfo` + `runPetCompatAnalysis`)
브랜치: `feat/pet-resume` (워크트리 `~/projects/durumi-saju-pet`) — 펫 코드는 아직 main에 없으므로 이 브랜치에 커밋해 PR #84에 태워 보낸다. **아직 미출시 → 프로덕션 결과 데이터 0건 → 라벨 텍스트 수정도 지금이 가장 싸다.**
LLM: Gemini API (`gemini-2.5-flash`, temperature 0.85) — Claude API 아님.

## 1. 문제 정의

**증상**: 강아지 결과의 `petVerdict` 등에 고양이 전용 행동 "꾹꾹이"(앞발 꾹꾹 누르기)가 섞여 나온다. 엔진은 `pet.species: "dog"`를 정확히 넘긴다(`lib/pet-compat.ts:364` `종: ${pet.species === "dog" ? "강아지" : "고양이"}`). LLM이 프롬프트에 놓인 고양이 어휘를 골라 쓰는 것.

**근본 원인**: 시스템 프롬프트의 "참고 표현 풀"이 **종과 무관하게 통째로** 주어진다. 실측 줄번호 (`lib/pet-compat.ts`):

| 줄 | 내용 | 문제 |
|---|---|---|
| 153~159 | `[참고 표현 풀]` 전체 | 종 구분 없이 단일 리스트 |
| 154 | `권력: 집안 실세, 묘르신, 냥느님, 폐하, ...` | 묘르신·냥느님 = 고양이 전용인데 무조건 노출 |
| 158 | `모순 짚기: ...골골송으로 무마, 식빵 한 번이면 사면...` | 골골송·식빵(자세) = 고양이 전용 행동 |
| 159 | `신조어: 집사·묘연·간택·냥줍·...·식빵·꾹꾹이·골골송·우다다·...·댕댕이·시고르자브종...` | 고양이 전용(꾹꾹이·골골송·식빵·냥줍·묘연·묘르신·냥느님·개냥이·아깽이·쮸릅·뚱냥이)과 개 전용(댕댕이·시고르자브종·뽀시래기·짱절미)이 한 리스트에 혼재 |
| 137 | viral 패턴 6 `호칭 격상 디스 (묘르신/냥느님/폐하)` | 예시 2/3가 고양이 전용 |
| 138 | viral 패턴 7 `방언/외래어 (시고르자브종/뽀시래기/짱절미)` | 반대로 개 편향 — 고양이 결과에 개 어휘 샐 경로 |
| 162~165 | `[종별 톤 분리]` | 아키타입(강아지=활발·충성 / 고양이=시니컬·황제)만 주고 **어휘 풀은 안 가름** |
| 197 | D등급 라벨 예 `"사주가 멀리 본 묘연"` | 묘연(猫緣) = 고양이 전용 — 강아지 D등급에도 이 예시가 보임 |
| 199 | `ruler ≥ 70이면 펫 권력 코드 (실세/폐하/묘르신)` | 묘르신이 무조건 후보 — headline 생성에 영향 |
| 310 | 외모 디스 예외 `"뚱냥이/돼냥이/털찐냥"은 OK` | 예외 목록이 고양이 어휘뿐 → 개 결과에서도 이 단어들이 "허용된 것"으로 학습됨 |

즉 LLM은 temperature 0.85에서 컨텍스트에 놓인 전체 풀에서 샘플링하는데, "종별로 갈라 써라"는 명시 지시가 없으니(아키타입 톤 지시만 있음) 개 결과에 고양이 어휘가 새는 것이 구조적으로 자연스럽다.

### 인접 발견 (같은 버그 계열 — 이번 스코프에 포함 권고)

`lib/pet-compat-scoring.ts:381` — **서버 결정 labelText의 D등급이 `"사주가 멀리 본 묘연"` 고정**. `pickLabelText()`는 species를 아예 안 받는다. 강아지가 D등급이면 서버가 직접 "묘연"을 박고, `runPetCompatAnalysis`가 이 값을 강제 덮어쓰기(`lib/pet-compat.ts:430`)하므로 프롬프트만 고쳐선 못 막는다. → §3-D에서 함께 수정.

### 인접 발견 2 (다른 계열 — 운영자 판단 요청, 이번 커밋에 1줄로 얹을지 결정)

`lib/pet-compat-scoring.ts:356` — S등급 labelText `"네가 더 매달리는 운명의 인연"`에 **"운명"** 이 들어 있다. 프롬프트 319~326줄은 "운명"을 *결과 어디에도 나오면 실패*로 규정하는데, 서버 라벨 자체가 위반. 종 혼입과 무관하지만 발견했으므로 보고. 수정은 1줄(예: `"네가 더 매달리는 팔자의 인연"`). **이 계획의 필수 범위는 아님 — 운영자 OK 시 같은 커밋에 포함.**

## 2. 설계 대안 비교

### ① species별 표현 풀을 코드에서 분기 주입
`PET_COMPAT_SYSTEM_PROMPT` const → `buildPetCompatSystemPrompt(species)` 함수로 바꾸고, 표현 풀·viral 패턴 예시·라벨 코드 예시를 [공용] + [해당 종 전용]만 삽입. 반대 종 어휘는 **컨텍스트에서 아예 제거**.

- 장점: 가장 강력. 샘플링할 어휘가 컨텍스트에 없으면 복사될 수 없다. temperature 0.85에서도 안전.
- 단점: 모델이 pretraining으로 아는 교차 어휘(꾹꾹이 등)를 스스로 지어내는 건 못 막음. 프롬프트가 함수화되어 history 관리가 약간 복잡(종별 2벌).

### ② 한 풀 유지 + 강한 금지 가드 문구
풀을 `[공용] / [강아지 전용] / [고양이 전용]`으로 라벨링만 하고 "반대 종 표현 절대 금지" hard guard 추가.

- 장점: 코드 변경 없음(문자열만 수정). history diff 단순.
- 단점: **현재 버그가 정확히 "지시만으로 가르기"의 실패 사례다.** 기존 [종별 톤 분리](162~165줄)라는 지시가 이미 있는데도 샜다. 반대 종 어휘가 컨텍스트에 남아 있는 한 temperature 0.85에서 누출 확률이 0이 안 됨.

### ③ ① + ② 결합 (분기 주입 + hard guard)
코드에서 종별 풀만 주입하고, 동시에 "반대 종 전용 어휘·행동 금지" 가드 문구(금지 단어 명시 리스트 포함)를 넣는다. 가드가 pretraining 유래 누출까지 커버.

- 장점: 컨텍스트 제거(구조적 차단) + 명시 금지(지식 유래 차단) 이중 방어. 두 실패 경로를 모두 막는 유일한 안.
- 단점: 수정 범위가 셋 중 가장 큼. 그래도 파일 1개 + scoring 라벨 1함수 수준.

**추천: ③.** 근거 — 이미 ②류 지시([종별 톤 분리])가 실패한 실측이 있고, 유료 LLM 호출이라 재생성 리트라이보다 프롬프트에서 원천 차단이 싸다. 후처리 런타임 가드(결과 grep 후 재시도)는 배틀 품질 검토 때(2026-06-10)와 동일하게 **저위험·보류** — 이번엔 넣지 않고, 검증(§5)에서 누출이 잔존하면 그때 재검토.

## 3. 추천안 상세

### A. 어휘 분류 (풀 재편 기준)

| 분류 | 어휘 |
|---|---|
| **고양이 전용** | 꾹꾹이, 골골송, 식빵(자세), 냥줍, 묘연, 간택, 묘르신, 냥느님, 개냥이, 뚱냥이·돼냥이·털찐냥, 아깽이, 쮸릅, 우다다, 하악질, 그루밍, 츄르, 캣타워, 야옹, "-냥" 어미 |
| **개 전용** | 댕댕이, 멍뭉이, 똥강아지, 시고르자브종, 뽀시래기, 짱절미, 멍멍·왈왈, 꼬리 프로펠러(격한 꼬리치기), 현관 마중, 산책(행동·시뮬 장면 포함) |
| **공용** | 집사(운영 결정: 공용 유지), 만렙, 1순위·0순위, 폐하, 집안 실세, 츤데레, 밥시계, 정시 출근, 생존형 협상, 영업, 푸시 알림, 와이파이, 자동 결제, 무릎 위 점령군, 시종 소환 벨, 망치·돌쇠 |

주: "식빵"은 자세 의미일 때만 고양이 전용이지만, 개 결과에서 빵 음식 비유로 쓸 일도 사실상 없으므로 **개 프롬프트에서는 단어 자체를 빼고 가드에도 넣는다** (grep 검증 단순화).

### B. 코드 구조 변경 (`lib/pet-compat.ts`)

1. 표현 풀·종속 예시를 조각 상수로 분리:
   ```ts
   const COMMON_POOL = `...공용 풀...`;
   const CAT_POOL = `...고양이 전용 풀 + 고양이 viral 예시(묘르신/냥느님 격상 디스 등)...`;
   const DOG_POOL = `...개 전용 풀 + 개 viral 예시(똥강아지 전무 격상 디스, 시고르자브종/뽀시래기/짱절미)...`;
   const CAT_GUARD = `...개 어휘 금지 가드...`;
   const DOG_GUARD = `...고양이 어휘 금지 가드...`;
   ```
2. `export function buildPetCompatSystemPrompt(species: PetSpecies): string` 신설 — 템플릿 리터럴로 기존 프롬프트 골격 + 해당 종 조각만 조립. 기존 `export const PET_COMPAT_SYSTEM_PROMPT`는 삭제(사용처는 `runPetCompatAnalysis` 내부뿐 — 실측 grep으로 외부 import 없음 확인).
3. `runPetCompatAnalysis`의 `callGemini(model, userInfo, PET_COMPAT_SYSTEM_PROMPT, ...)` → `callGemini(model, userInfo, buildPetCompatSystemPrompt(input.pet.species), ...)`.
4. 종속 예시 치환 목록:
   - 137줄 패턴 6: `호칭 격상 디스` 예시를 종별 주입 (고양이=묘르신/냥느님/폐하, 강아지=폐하/회장님/똥강아지 전무)
   - 138줄 패턴 7: `방언/외래어` 예시를 종별 주입 (강아지=시고르자브종/뽀시래기/짱절미, 고양이=아깽이/쮸릅/냥느님)
   - 154·158·159줄: §A 분류대로 공용+해당 종만
   - 197줄 D 라벨 예: 고양이=`"사주가 멀리 본 묘연"`, 강아지=`"사주가 멀리 본 인연"`
   - 199줄 권력 코드: 고양이=`(실세/폐하/묘르신)`, 강아지=`(실세/폐하/회장님)`
   - 310줄 외모 디스 예외: 고양이=`뚱냥이/돼냥이/털찐냥`, 강아지=`뚱댕이/통통강아지`
   - 285줄 scene 예시: 고양이 프롬프트에서 "산책" 제거, 대체 장면(창밖 감시/캣타워/그루밍 타임/츄르 협상) 제시
5. `buildPetCompatUserInfo`의 `종:` 줄(364줄) 바로 아래에 1줄 리마인더 추가 (recency 강화):
   ```
   - ★ 이 아이는 {강아지|고양이}다. 결과 전체에서 {고양이|강아지} 전용 행동·용어를 쓰면 실패.
   ```

### C. hard guard 문구 초안 (시스템 프롬프트 [종별 톤 분리] 섹션에 병합)

강아지용 (`DOG_GUARD`):
```
[종 어휘 가드 — 어기면 실패]
이 펫은 강아지다. 결과 전체(모든 필드 합산)에서 고양이 전용 행동·용어 절대 금지:
꾹꾹이, 골골송, 식빵, 냥줍, 간택, 묘연, 묘르신, 냥느님, 개냥이, 뚱냥이, 아깽이,
쮸릅, 우다다, 하악질, 그루밍, 츄르, 캣타워, 야옹, "-냥" 어미.
행동 묘사도 강아지가 실제로 하는 행동만 써라. 강아지는 골골송을 부르지 않고
식빵 자세를 하지 않고 꾹꾹이를 하지 않는다.
```

고양이용 (`CAT_GUARD`):
```
[종 어휘 가드 — 어기면 실패]
이 펫은 고양이다. 결과 전체(모든 필드 합산)에서 강아지 전용 행동·용어 절대 금지:
댕댕이, 멍뭉이, 똥강아지, 시고르자브종, 뽀시래기, 짱절미, 멍멍, 왈왈, 꼬리 프로펠러.
산책 장면 금지 — 시뮬레이션 scene에도 "산책"을 쓰지 말고 창밖 감시·캣타워·그루밍·
츄르 협상 등 고양이 장면으로 골라라. 고양이는 산책 가자고 목줄 물어오지 않는다.
```

### D. 서버 라벨 수정 (`lib/pet-compat-scoring.ts`)

- `pickLabelText(grade, scores)` → `pickLabelText(grade, scores, species: PetSpecies)`. 호출부 `computePetCompatScores`는 `signals`에서 species 접근 가능한지 확인 후 전달 (없으면 `computePetCompatScores(signals, species)`로 시그니처 확장 — 호출부는 analyze/dev-test/test 스크립트 3곳).
- 381줄 D 라벨: `species === "cat" ? "사주가 멀리 본 묘연" : "사주가 멀리 본 인연"`.
- **`PET_COMPAT_SCORING_VERSION`(현재 v4) bump 불필요 판단**: 점수 로직 무변경 + 미출시라 캐시된 결과 0건. 단, 만약 점수·시그널에 손대게 되면 그때는 bump.
- (운영자 OK 시) 356줄 "운명의 인연" → "팔자의 인연" 1줄 동승.

### E. 깨지면 안 되는 것 (회귀 체크 목록)

- **톤 규칙**: 펫=귀엽게 놀리기(119~125줄), 의료 진단어·인격 평가·관계 단절·비교 비하 금지(306~316줄) — 풀 재편 시 이 섹션 문구 불변.
- **12지 연주 기준 룰**(168~173줄) — 손대지 않음.
- **표현 중복·단어 반복 금지**(149~151줄), **"운명"·"100%"·"절대" 등 금지 단어**(319~326줄) — 불변. 가드 추가로 이 규칙들과 충돌 없음(가드는 어휘 추가 제한만 함).
- **한자 병기 상한 3개 룰**(293~301줄, 커밋 09508a6에서 강화된 것) — 불변.
- **출력 JSON 스키마**(249~285줄) — 필드·형식 무변경. `runPetCompatAnalysis`의 서버값 강제 덮어쓰기(421~430줄) 로직 무변경.
- **점수·등급·labelText 서버 결정 원칙** — LLM에 종별 프롬프트를 줘도 이 원칙은 그대로 (D 라벨 종 분기도 서버에서).
- 프롬프트 골격(섹션 순서·헤더)은 최대한 유지 — diff 리뷰 가능하게, 종속 부분만 조각 치환.

### 자동 그렙 체크

응답의 **텍스트 필드 전부**(`label.headline`, `label.text`, `manual.*`, `ownerVerdict`, `petVerdict`, `simulations[].scene/prediction`, `futureLine`, `finalLine`, `disclaimer`)를 합쳐 반대 종 어휘 배열과 대조. 일회용 스크립트(예: `scripts/check-pet-species-leak.mts`, 검증 후 삭제 — 잔여 파일 정리 원칙):

```ts
const CAT_ONLY = ["꾹꾹이","골골송","식빵","냥줍","간택","묘연","묘르신","냥느님","개냥이","뚱냥이","돼냥이","털찐냥","아깽이","쮸릅","우다다","하악질","그루밍","츄르","캣타워","야옹"];
const DOG_ONLY = ["댕댕이","멍뭉이","똥강아지","시고르자브종","뽀시래기","짱절미","꼬리 프로펠러","산책","멍멍","왈왈"];
// result JSON을 깊이 순회해 string 필드 전부 concat → species가 dog면 CAT_ONLY, cat이면 DOG_ONLY 매칭을 필드 경로와 함께 출력. 매칭 0건이어야 통과.
```

주의: 단일 글자("냥","묘","멍") 매칭은 오탐(미묘·분위기냥 등)이 많아 **단어 단위로만** 대조. "간택"은 문맥상 임금 간택 비유로 나올 수도 있으니 매칭 시 사람이 해당 문장 읽고 판정(자동 실패 처리 X — flag & review).

### 합격 기준
- 개 결과 3건 × CAT_ONLY 매칭 0 (간택류 flag는 수동 판정)
- 고양이 결과 2~3건 × DOG_ONLY 매칭 0, scene에 "산책" 없음
- D등급 케이스: labelText가 종에 맞음("묘연"은 고양이만) + disclaimer 실출력
- 기존 룰 회귀 없음: 한자 병기 ≤3, "운명" 0건, JSON 파싱 성공 6/6

누출이 1건이라도 나오면: 가드 문구를 해당 어휘 중심으로 강화 후 그 종만 2건 재생성(추가 호출 최소화). 2라운드에도 남으면 그때 런타임 후처리 가드(§2에서 보류한 것)를 재검토.
