## 1. 배경과 목표

두루미사주의 모든 모듈(개인사주·today·yearly·marriage·wealth·career·pet·battle)은 생년월일 결정론 엔진 위에 올라가 있다. 타로는 그 위에 얹는 **두 번째 세계**다.

목표는 셋이다.

1. **신규 유입** — "타로"는 사주보다 검색·SNS 진입이 크다
2. **추가 매출** — 기존 유저의 코인 소비처 확대
3. **재방문** — 사주는 94%가 one-and-done이다. 타로는 반복이 자연스럽다

### 왜 지금 만들 만한가 (리서치 근거)

- 국내 포털 2 + CP 2 + 앱 6종 실측 결과 **사주 원국을 타로 해석에 실제로 물리는 제품이 없다.** 사주플러스는 도메인을 분리해뒀고(`unse.` / `tarot.`), 오즈의타로는 생년월일을 소울카드에만 쓴다
- **네이버·다음은 타로 코드 경로 자체가 없다.** 네이버 운세 모듈 JS 분기가 `생년월일/띠별/별자리/신년` 4종뿐이다. 타로 수요는 전량 CP 유료상품으로 흘러간다
- **재질문 하드 락이 시장에 0건이다.** 그 대가로 "같은 걸 두 번 했는데 다르게 나온다"는 신뢰 붕괴 리뷰가 반복 확인된다

## 3. 제품 정의

### 3.1 브랜드 스위처

현재 브랜드명은 코드 122곳에 있지만 **화면에 보이는 건 2곳뿐**이다 — `app/(components)/LandingHeader.tsx:10`, `app/login/page.tsx:15`. 나머지는 SEO 메타와 사전 데이터라 건드리지 않는다.

`<h1>사주보는 두루미</h1>` 를 `BrandSwitcher` 컴포넌트로 교체한다.

- 탭하면 시트가 열리고 **사주 / 타로 / 별자리(준비중)** 가 뜬다
- 고르면 해당 세계의 홈으로 이동
- 별자리는 비활성 상태로 노출한다. 유저가 첫날부터 "여기 계속 늘어나는구나"를 느끼게 하는 게 목적이다
- 세계 구분은 **accent 컬러와 두루미 복장만**. 배경 다크·Pretendard·카드 레이아웃 등 디자인 시스템은 그대로 간다. 사이트가 쪼개진 느낌 없이 "같은 두루미가 다른 걸 본다"가 되어야 한다

### 3.2 주제 구성

사주 쪽에 이미 결혼운·재물운·커리어운이 있다. 겹치면 같은 사이트에서 같은 걸 두 번 파는 셈이다. 축을 가른다.

- **사주** = 당신은 어떤 사람이고 흐름은 어떻게 흘러가는가 (타고난 것)
- **타로** = 지금 눈앞의 이 선택, 할까 말까 (결정하는 것)

그래서 타로 주제는 전부 **"~해도 될까?"** 형태의 결정형이다.

| 주제군 | 세부 질문 (초안) |
|---|---|
| **일·커리어 결정** | 이직해도 될까 · 퇴사해도 될까 · 이 회사로 가도 될까 · 창업해도 될까 · 지금 자리에 남아도 될까 |
| **관계·연애 결정** | 이 사람 계속 만나도 될까 · 고백해도 될까 · 헤어져야 할까 · 재회해도 될까 · 이 관계 손절해야 할까 |
| **도전·선택 결정** | 다시 도전해도 될까 · 떠나도 될까(이사·유학) · 지금 시작해도 될까 · 둘 중 뭘 골라야 할까 |

돈·물건 결정군은 이번 출시에서 제외한다.

세부 질문 목록은 초안이며 구현하며 조정한다. 각 질문은 고유 `question_id`를 갖고, 이 값이 재사용 가드 키에 들어간다.

### 3.3 스프레드

3장. 과거/현재/미래가 아니라 **결정형에 맞춘 배치**다.

| 자리 | 의미 |
|---|---|
| 1 | 지금 이 상황의 진짜 얼굴 |
| 2 | 그 선택을 했을 때 열리는 길 |
| 3 | 두루미의 조언 — 무엇을 붙잡고 무엇을 놓을지 |

**클래리파이어 1장**은 별도다. 오늘 같은 질문으로 다시 들어온 유저에게만 열린다. 자리 의미는 **"내가 못 보고 있는 것"**.

### 3.4 리딩 플로우

```
/tarot
  → 주제군 선택 (3군)
  → 세부 질문 선택
  → 내 상황 입력 (자유 텍스트)
  → [무료] 셔플 → 78장 부채꼴 전개 → 3장 직접 선택 → 한 장씩 뒤집기
  → [여기서 결제 10알] 사주 결합 해석 전문
  → 공유 카드 이미지
```

**뽑기까지는 무료, 해석이 유료다.** 이 경계는 두 가지를 동시에 푼다.

1. **법적 요건** — 전자상거래법 제17조⑥은 "시험 사용 상품 등의 제공" 없이는 청약철회 제한을 주장할 수 없게 한다(§10-1). 뽑기 무료 공개가 시행령 제21조의2의 "일부 이용의 허용"에 해당한다
2. **전환** — 카드를 이미 뒤집어 본 상태에서 결제하므로 몰입이 최고조다

무료 리딩 티어를 만드는 게 아니다. **해석 전문이 10알**이고 뽑기 연출이 미리보기다. (운영자 확정 2026-07-29)

### 3.5 재질문 규칙

**리딩 단위로 건다.** 카드 층이 아니다.

- 셔플은 서버가 실제로 난수로 섞고 그 순서를 저장한다
- 유저가 고른 자리의 카드가 그대로 나온다. **다른 자리를 골랐으면 다른 카드가 나온다.** 고르는 행위는 진짜다
- 오늘 같은 주제·같은 질문·같은 상황으로 다시 들어오면 셔플 화면을 열지 않는다. "오늘의 답은 이미 나왔습니다" + 기존 리딩을 보여준다. **코인 미차감**
- 대신 **클래리파이어 한 장**을 제안한다 — "내가 못 보고 있는 것"
- 상황 텍스트가 바뀌거나 날이 바뀌면 새로 섞는다
- **정/역방향은 셔플 시점에 함께 결정**해 `deck_order`에 담는다. 유저가 자리를 고른 뒤에 방향을 정하지 않는다 — 그러면 다시 "뽑기 전부터 정해진 것"이 되어버린다

타로 전통에서 "같은 질문을 반복하지 말라"는 원칙은 실재하고, 커뮤니티 주류 통념은 "금지"가 아니라 **"즉시 재뽑기는 혼란만 키운다 → 클래리파이어 한 장을 뽑아라"**다(Biddy Tarot, 타로 포럼 다수). 이 설계는 그 통념을 그대로 구현한 것이다.

## 4. 뽑기 경험

카드가 해석의 도구가 아니라 **그 자체로 갖고 싶은 물건**이어야 한다. 포켓몬 카드의 질감을 목표로 한다.

### 4.1 단계별 연출

| 단계 | 연출 | 기술 |
|---|---|---|
| 셔플 | 카드 뭉치가 섞이는 모션 | GSAP timeline |
| 전개 | 78장 부채꼴 (`rotate(θ) translateY(-r)` + `transform-origin: 50% 120%`) | transform만. `top/left/margin` 금지 |
| 선택 | 유저가 3장 탭. 선택 순서 보존 | — |
| 뒤집기 | `rotateY(180deg)` + `backface-visibility: hidden` | 뒤집는 동안 blend 레이어 OFF |
| 결과 | 홀로그램 광택 + 기울기 반응 | 뽑힌 3장에만 |

### 4.2 성능 — 반드시 지킬 것

**78장 전부에 홀로 효과를 걸면 iOS에서 탭이 죽는다.** 카드 1장당 컴포지터 레이어가 15~20MB로 추정되어 78장이면 1GB를 넘긴다. `pokemon-cards-css` 원작자도 "1장만 인터랙티브"로 제한해뒀다.

- **부채꼴 단계**: 뒷면 이미지 **1장**을 78개 노드가 참조. shine/glare 엘리먼트 자체를 렌더하지 않는다. 전송량 ~20KB
- **결과 단계**: 뽑힌 3장에만 `.interactive` 부여 → shine + glare + `will-change` + `translate3d` 승격
- `will-change`를 78장에 미리 걸지 않는다. 애니메이션 직전 부착, 종료 후 제거
- stagger는 CSS 변수 `--i` + `transition-delay`로. 78개 tween 금지
- 가상화 불필요 (78장은 임계치 아래)

### 4.3 라이선스 주의

`pokemon-cards-css`는 **GPL-3.0이라 코드를 복붙하면 안 된다.** 기법(gradient + blend + mask 조합)은 아이디어라 자체 재구현은 문제없다. 틸트는 `react-parallax-tilt`(MIT, 2.9kB). 셔플은 GSAP(2025-04-30부터 전 플러그인 무료·상용 가능).

### 4.4 기울기

iOS Safari는 `DeviceOrientationEvent.requestPermission()`이 필수이고 **버튼 클릭 같은 사용자 제스처 안에서만** 호출 가능하다. 자동으로는 절대 안 된다.

- 기본은 **터치 드래그 틸트**
- 카드 아래 "기울여서 보기" 버튼 → 탭하면 `requestPermission()`
- 권한 상태 조회 API가 없으므로 결과를 `localStorage`에 저장해 버튼 노출을 판단
- 절대 alpha/beta/gamma 금지. 첫 이벤트를 baseline으로 잡고 **상대값**만 쓴다. 클램프 수평 ±16° / 수직 ±18°

### 4.5 사운드

**기본 OFF.** 내레이션 기본 ON 때문에 리뷰어가 앱을 버릴 뻔한 사례가 있다.

- 첫 `pointerup`에서 `AudioContext.resume()` + 0-length 버퍼 재생으로 unlock
- iOS는 무음 스위치가 켜져 있으면 Web Audio가 아예 안 들린다. 우리 버그가 아니지만 "소리 안 나요"로 접수된다. `navigator.audioSession.type = 'playback'`로 완화 시도 (Safari 전용)
- 첫 화면에 "소리 켜고 뽑기 / 소리 없이 뽑기" 선택을 두면 unlock 제스처와 의도를 동시에 확보한다

### 4.6 이미지

78장을 다 로드할 필요가 없다. 부채꼴은 뒷면 1장, 결과는 앞면 3장 — **실제 전송은 4장**이다.

- AVIF 우선 + WebP 폴백. `next.config.js`에 `images: { formats: ['image/avif', 'image/webp'] }`
- 앞면 소스 폭 960px (DPR3에서 320 CSS px 대응). AVIF q65에서 40~80KB 예상
- 뒷면은 반복 패턴이라 10~20KB
- 앞면은 **셔플 애니메이션 시작 시점에 prefetch**. 2초 동안 받으면 뒤집힐 때 캐시에 있다
- **스프라이트 시트 금지** — 4096×4096 상한에 78장을 넣으면 장당 460px로 화질이 무너지고 67MB를 상주시킨다

## 5. 카드 덱

**두루미 캐릭터 78장 풀덱.** 메이저 22장이 아닌 이유는 수집 대상이 되어야 하기 때문이다.

### 레어도를 넣지 않는 이유

1. 카드에 등급을 매기면 "좋은 카드 = 좋은 운세"가 되어 유저가 해석을 안 읽고 레어 뽑기만 하게 된다. 타로 해석이 껍데기가 된다
2. 유료 + 랜덤 + 레어도는 확률형 아이템 프레임으로 읽힌다. 운세 서비스가 굳이 그 프레임을 쓸 이유가 없다

가져올 것은 레어도가 아니라 **질감과 소장감**이다.

### 저작권

- **US Games 라이선스는 돈 주고도 못 산다.** 정책 원문에 "자동화 타로 리딩용 이미지는 Tarot.com과의 독점 계약으로 NOT AVAILABLE"이라고 명시돼 있다
- 1909년 원본 PCS 아트워크는 **한국에서 퍼블릭 도메인**이다 (Smith 1951년 사망 → 사후 50년 → 2001-12-31 만료, 소급 부활 없음). 단 **현대 채색판 스캔은 안 된다**
- 그림이 PD여도 **"Rider-Waite"는 등록상표**다. 서비스명·설명·스토어 제목에 쓰지 않는다
- **순수 AI 생성 카드 아트는 배타적 권리가 없다.** 남이 그대로 복제해도 못 막는다. 보호받는 건 78장의 선택·배열, UI, 텍스트뿐이다

### 그래서 제작 방식

1. 두루미 캐릭터로 78장 생성
2. **사람 손이 들어간 후보정을 반드시 거친다** — 이게 자산화의 유일한 경로다
3. **78장의 선택·배열을 편집저작물로 문서화**해 기록을 남긴다
4. Midjourney를 쓴다면 **Stealth 필수** — 기본값이 "공개·리믹스 허용"이라 경쟁사가 그대로 가져가도 저작권으로도 약관으로도 못 막는다

생성은 유료 작업이므로 **운영자 승인 후 착수**한다.

## 6. 해석 엔진

### 6.1 사주 결합

타로 해석에 원국을 실제로 물린다. 이게 국내 미개척 영역이자 두루미의 유일한 차별점이다.

- 로그인 유저는 저장된 사주를 자동 사용, 비회원은 입력 플로우(`/start`)를 거친다
- 비회원은 기존 `lib/guest-token.ts` 게스트 토큰을 그대로 쓴다. `tarot_readings.user_id`는 로그인 유저 uuid 또는 게스트 토큰 식별자를 받으며, 재사용 가드 키도 동일하게 동작한다
- 카드 의미를 **원국의 렌즈로 굴절**시킨다. 같은 카드도 사람에 따라 다르게 읽혀야 한다
  - 예: 관성이 약한 사람의 "이직해도 될까"에 나온 전차 카드 → "밀어붙일 힘은 있으나 그걸 지탱할 구조가 아직 없다"
- 3번 자리(조언)에 대운·세운 흐름을 반영한다
- 주제군별로 사주의 어느 축을 볼지 매핑한다 (일·커리어 → 관성/식상, 관계 → 재성/관성, 도전 → 인성/식상)

### 6.2 프롬프트 원칙

기존 모듈과 같은 파이프라인(Gemini + surgical rewrite + guard)을 탄다. 타로 고유 원칙은 셋이다.

1. **동의만 하는 해석 금지.** 유저가 원하는 답을 주는 게 아니라 카드가 말하는 걸 말한다. AI 타로에 대한 최대 불만이 아첨(sycophancy)이라는 게 연구로 확인됐다
2. **결정을 대신 내리지 않는다.** "하지 마" / "해" 단정 금지. 무엇을 보고 결정할지를 준다
3. **불안 고지 + 결과 약속 조합 절대 금지.** 이건 취향이 아니라 형사 리스크다 (§10-11)

### 6.3 품질 가드

기존 `marriage_guard_violations` / `wealth_guard_violations` 패턴을 그대로 복제해 `tarot_guard_violations`를 만든다. 출시 후 실측 full_json + guard_violations + 독립 critic 루프를 돌린다.

타로 고유 가드 항목:
- 뽑히지 않은 카드를 해석에 언급하지 않는가 (fabrication)
- 카드 정/역방향과 해석 톤이 일치하는가
- 사주 원국 정보가 실제 원국과 일치하는가
- 성사 단정·불안 조장 표현이 없는가

## 7. 과금

| 항목 | 비용 |
|---|---|
| 뽑기 + 카드 공개 (그림 · 이름 · 정/역방향까지) | 무료 (미리보기 겸 법적 요건) |
| 해석 전문 | **10알** |
| 클래리파이어 1장 | **5알** |

무료 구간에서 **해석 텍스트는 한 글자도 노출하지 않는다.** 카드 그림·이름·방향만 보여준다. 카드 의미를 아는 유저는 짐작할 수 있지만, 상품의 값어치는 카드 뜻풀이가 아니라 **그 카드를 이 사람 원국으로 굴절시킨 해석**에 있으므로 잠식되지 않는다. 오히려 숨기지 않는 편이 신뢰에 유리하다.

참고로 국내 CP 실측 단가는 포춘82 타로 1,650~13,500원("그 사람과 결혼까지 간다면?" 7,500원), 사주닷컴 마담 쓰리카드 5,000원이다. 10알은 보수적인 편이다.

### 재사용 가드

기존 marriage/career 패턴을 그대로 가져온다.

- `spend_coins` RPC → `tarot_result_unlocks` insert
- unique 키 = `(user_id, question_id, situation_hash, reading_date)`
- orphan unlock 처리: `created_at`이 3분 이내면 409("분석 중"), 초과면 멱등 환불 후 재결제 — `marriage/analyze/route.ts`의 `ORPHAN_GRACE_MS` 로직 미러
- **"차감 1 = 리딩 1" 불변식**을 지킨다

## 8. 데이터 모델

```sql
-- 리딩 본체
tarot_readings (
  id            uuid pk,
  user_id       uuid,
  topic         text,          -- 'career' | 'relationship' | 'challenge'
  question_id   text,          -- 세부 질문 고유값
  situation     text,          -- 유저가 적은 상황
  situation_hash text,         -- 재사용 판정 키
  reading_date  date,          -- 날짜 단위 가드
  deck_order    jsonb,         -- 서버가 섞은 78장 순서 (감사용)
  picked        int[],         -- 유저가 고른 위치 (순서 보존)
  cards         jsonb,         -- 확정된 3장 + 정/역방향
  full_json     jsonb,         -- 해석 결과
  created_at    timestamptz
)

-- 결제 언락
tarot_result_unlocks (
  user_id, reading_id, order_id, created_at,
  unique (user_id, question_id, situation_hash, reading_date)
)

-- 클래리파이어
tarot_clarifiers (
  id, reading_id, card jsonb, text jsonb, order_id, created_at
)

-- 품질 가드
tarot_guard_violations (기존 marriage/wealth 스키마 복제)
```

`deck_order`를 저장하는 이유는 나중에 "유저가 다른 자리를 골랐으면 뭐가 나왔을까"를 감사할 수 있어야 하고, 셔플이 진짜였음을 증명할 수 있어야 하기 때문이다.

도감을 지금 만들지 않더라도 `cards`가 쌓이므로 나중에 화면만 붙이면 된다.

## 9. 공유 카드 이미지

**Puppeteer 계열은 검토조차 하지 않는다.** `@sparticuz/chromium`만 50MB급인데 이 프로젝트는 이미 `public/stories` 214MB로 Vercel 250MB 함수 한도를 터뜨린 이력이 있다.

- **1순위**: 빌드 타임에 78장 정적 생성 → `public/og/card-{id}.png`. 함수 번들 증가 0, 콜드스타트 0
- 유저별 요소(닉네임 등)가 필요하면 `next/og` + **서브셋 ttf**. 한글 풀셋은 500KB 한도를 그냥 넘으므로 `pyftsubset`으로 필요한 글자만 추출(카드 이름 78개 + 고정 문구 + 숫자)한다. woff2는 지원하지 않으므로 ttf/otf로 출력
- 산출물이 함수 트레이싱에 딸려 들어가지 않도록 `outputFileTracingExcludes`에 추가한다. 214MB 사고의 재발 경로가 정확히 이것이다

## 10. 법적 요건

### 🔴 이번 작업에서 반드시 구현

**1. 시험 사용 상품 제공** — 전상법 제17조⑥ + 시행령 제21조의2
미이행 시 "열람했으니 환불 불가" 주장 **자체가 불성립**한다. 환급 거부 시 2천만원 이하 과태료.
→ §3.4의 "뽑기 무료 공개"가 이 요건을 충족한다. **개발 일정에서 가장 먼저 잡는다.**

**2. 미성년자 취소권 고지** — 전상법 제13조③
결제 화면에 "법정대리인 동의 없으면 취소 가능" 명시. 미고지 시 1천만원 이하 과태료.

**10. 확률을 상품 매력으로 내세우지 않기** — 전상법 제21조①1호
"희귀 카드"·"당첨" 등 확률 기대 유발 표현 회피. 레어도를 안 넣기로 한 결정과 같은 방향이다.

**11. 불안 고지 + 결과 약속 조합 금지** — 대법원 2016도12460
이건 과태료가 아니라 **사기죄**다. 프롬프트 가드에 넣는다.

**13. AI 생성 카드에 배타적 권리 기대 금지** — 저작권법 제136조②2호
사람이 창작한 것처럼 저작권 등록하지 않는다. 후보정·선택배열 기록으로 편집저작물 방어.
