# 결혼운/애정운 심층 검사 — 설계 스펙

- 작성일: 2026-07-18
- 상태: 승인됨 (Fable 사용자가치 검증 반영)
- 파일럿: 3종 심층 운세 검사(결혼·재물·커리어) 중 **1호 = 결혼운/애정운**
- 관련 라인업 계획: 사주 라인업 고도화 마스터 플랜(Phase 2 톤 통일)의 확장

---

## 1. 목적과 포지셔닝

개인사주 결과의 "연애운 점수 한 줄 + 코어피어" 요약 **뒤에 있는 이유**를, **동일한 원국(만세력)을 확대**해 결혼·애정 영역만 끝까지 파고드는 심층 리포트.

- 새 사주를 뽑는 게 아니라 **같은 차트를 깊게** 본다. → 메인 결과와 **모순 금지**(일관성 하드 규칙).
- 궁합(펫·커플)과 다름: 이건 *본인 사주 안의* 결혼운이지 두 사람 관계가 아니다.

### 고유 값어치 3축 (재탕 방지의 근거)

Fable 실측: 개인사주 연애 섹션(`lib/analysis.ts` [섹션 5])이 이미 관성/재성 구조 + 도화·홍염·원진 + 연애상태(솔로/연애중/기혼) 맞춤 + 용신별 이상형 한 줄까지 다룬다. 따라서 심층검사가 10알의 값을 하려면 값어치는 **아래 3곳에서만** 나온다:

1. **배우자궁(일지) 진단** — 개인사주에 명시 블록 없음. 진짜 신규.
2. **시기론(결혼/부부운 타이밍)** — 개인사주는 "현재 대운 유불리 1~2개"가 전부. 대운·세운이 배우자성/일지를 활성화하는 연도 계산은 신규.
3. **기혼 트랙** — 개인사주 연애 섹션은 기혼자에게 구조적으로 얕음. 35~54 여성 주력층에서 기혼 비중이 높아 실질 볼륨.

→ 나머지 블록(배우자성 분석·연애 패턴)은 개인사주와 **정면 충돌 구간**. 아래 §6 차별화 하드 규칙으로 방어.

## 2. 입력 (관계상태 4분법 — 프리필 + 원탭 확인)

### 검증된 사실 (입력 쪽 실측)
- `relationship_status`(솔로/연애중/기혼)는 개인사주 **가입/입력 시 필수 수집**(`app/api/intake/session/route.ts:18`에서 미입력 거부). → 개인사주를 한 유저는 전원 프로필에 저장돼 있음.
- `getPrimarySajuData()`(`lib/server/get-primary-saju.ts`)가 **`relationshipStatus` + `gender`를 이미 반환**. gender는 배우자성 판별(여명=관성/남명=재성)에 필수인데 이미 확보됨.
- 따라서 blind 재질문 불필요 — 저장값 프리필로 마찰 최소화.

### 입력 설계
- primary 사주 재사용 (`from-primary`가 원국·십성·신살·대운 + relationshipStatus + gender를 읽음).
- **관계상태 4분법**: `솔로 / 연애중 / 기혼 / 다시 혼자(이혼·사별)`
  - 저장된 3분법 값으로 **프리필** → **원탭 확인** 화면(맞으면 그대로 진행).
  - **'다시 혼자'는 저장 3분법에 없는 4번째 옵션** → 사용자가 정정 선택. (프로필 스키마는 안 건드림; 이 검사 내부에서만 4분법 수집)
  - 근거(Fable): 미혼/기혼 2분법은 정보 후퇴. **'연애중'** = 최고 구매의도 세그먼트("이 사람이랑 결혼할까"). **'다시 혼자'** = 35~54 여성층 무시 못 할 비중, 오배정 시 리포트 치명적으로 어색(존재하지 않는 배우자 화합 열쇠 등).
  - 표현은 시니어 친화(한 화면에 담기는 큰 버튼). "결혼=필수" 전제 어투 금지(비혼 배려).
- 매핑: 저장 솔로→솔로, 연애중→연애중, 기혼→기혼; 다시 혼자는 신규 선택값.

## 3. 엔진 모듈 (1순위 작업, 3종 라인업 공용 자산)

`lib/marriage-facts.ts` — `deriveMarriageFacts(chart, sex, maritalStatus)` → 결정론적 사실 객체.

> 이 모듈이 **프롬프트보다 선행**한다. 이게 없으면 7블록 전부 LLM 자유생성 = 정확히 금지된 재탕. (Fable 지적: "결정론 주입"의 절반이 미구축 상태였음)

실측: 엔진 프리미티브는 이미 존재 → 밑바닥이 아니라 **조합 계층**이다.
- 있음: `getTenStar`/`calculateTenStars`(정관·편관·정재·편재 판별), `BRANCH_INFO`(지장간), `judgeStrength`(신강신약), `findRelationships`/`getPairRelation`(합충형해원진), `findShinsal`(도화·역마·화개), 공망(주별 위치), `determineYongshin`.
- 없음(이 모듈이 조합해 새로 산출):
  1. **배우자성 위치·강약** — 여명=관성(정관/편관), 남명=재성(정재/편재)을 기둥별로 탐지 + 강약.
  2. **관살혼잡(官殺混雜)** — 정관+편관 혼재 유무·위치·거류(去留). 여명 결혼운 감정의 핵심.
  3. **일지 지장간 십성** — 배우자의 '숨은 성격'(겪어봐야 아는 면). 블록 4 개인화의 핵심 재료.
  4. **배우자성 합거/충거** — 관성이 합으로 묶이거나 충으로 깨진 '있는데 못 쓰는' 케이스.
  5. **일지 공망** — 배우자궁 공망(민감 해석 → 톤 가이드 연동).
  6. **타이밍 3트리거 연도 리스트**: (a) 세운 지지가 일지와 합(배우자궁 동함) (b) 배우자성이 대운·세운에 투출 (c) 도화·홍염 세운.
  7. **무관/무재 폴백 체인**: 원국에 배우자성 없으면 "배우자궁으로 대체 판단 + 대운에서 들어올 때가 인연" (타이밍 블록과 자연 연결). "인연이 약합니다"로 직행 금지.

### 신살 정책
- **제외**: 홍란·천희 — 현 엔진 미보유 + 자평 정통 아닌 주변 계보. fabrication 방지 원칙상 리포트에서 뺀다.
- **노출 금지 리스트**: 과숙살·고신살·상부살 등 근거 얇고 공포 효과만 큰 전통 흉살. 감지돼도 노출 금지.

## 4. 리포트 블록 (엔진 재료의 *조합 해석만* LLM 담당)

### 공통 코어 (모든 상태)
1. **결혼운 등급** — SS~C. **연애운 점수 → 등급 밴드 서버 결정론 매핑**(LLM 재량 금지; title 톤 개편 때의 scaffold 방식 재사용). 같은 사람이 연애운 78점인데 결혼운 B가 나오면 신뢰 붕괴.
2. **배우자궁 진단** — 일지 상태(안정/불안정, 합충형해원진, 공망).
3. **배우자성 분석** — 유무·강약·위치·종류(정관 vs 편관 등)·합거/충거. 무관/무재는 폴백 체인.

### 상태별 강조
- **솔로**: 4)끌리는/맞는 배우자상(일지 지장간 십성·배우자성 종류/위치/오행 기반) 5)나의 연애·관계 패턴과 맹점 6)결혼 타이밍(향후 인연 창 vs 조심할 시기)
- **연애중**: 4)관계에서 반복하는 패턴 + 결혼으로 넘어갈 때의 관문 5)맹점 6)타이밍. (상대 궁합은 범위 밖 → 궁합 상품 CTA 지점)
- **기혼**: 4)관계에 **내가 가져오는 것**(약속 범위 축소, §6 참조) 5)화합의 열쇠·갈등 지점(두 사람 사이 패턴으로만) 6)부부운 흐름·조심할 시기
- **다시 혼자**: 과거 단정 없이, 앞으로의 인연 창 중심 + 관계 패턴 재정비.

### 공통 마무리
7. **실천 조언** — **반드시 진단 블록의 특정 근거에 결선**(일지 충 근거면 그 상황 회피법, 도화 근거면 활용법). **근거 태그 없는 조언 문장은 후처리에서 컷.** "대화 많이 하세요" 류 금지.
8. **궁합 상품 CTA** — "배우자/상대 사주까지 합치면"으로 부부·커플 궁합 상품 연결(운영자 데이터상 유효했던 '궁합' 방향).

## 6. 하드 규칙 (quality-gate / postprocess 강제)

### 차별화 규칙
- 개인사주가 이미 말한 것 **반복 금지**.
- 반드시 **한 단계 아래 해상도**로 내려간다: 어느 기둥, 어느 지장간, 몇 년(연도).

### 일관성 규칙 (3-layer 사고 재발 방지)
- 새 검사는 primary 원국을 그대로 읽어 파생만 한다(새 계산·다른 값 금지).
- 메인 result와 불일치 차단 → **공유 검증 helper로 전수 점검**(과거 coreFear 3-layer 불일치 사고 교훈).
- 등급은 §4-1 결정론 매핑으로 점수와 묶는다.

### 여명 정서 안전장치 (이 검사의 진짜 리스크)
전통 결혼운 감정 레퍼토리가 하필 중년 여성에게 가장 잔인하고("상관견관→남편 극한다", "관살혼잡→남자문제", "일지충→이별수"), LLM 학습데이터에 그대로 있음. 명시 규칙 없으면 샌다.
1. **단정 금지**: 이혼·사별·외도 예언 절대 금지. 구조는 '경향 + 관리법'으로만.
2. **극(剋) 재해석**: 상관견관 등 → 사람 탓이 아니라 소통 패턴으로 번역("표현이 직설이라 지적으로 느껴질 수 있는 구간").
3. **조심할 시기 = 대응법 세트 강제**: 시기만 던지고 끝나는 문장 금지.
4. **기혼 도화·홍염 = 매력·대인 인기로만**. 외도 암시 뉘앙스 negative 규칙.
5. **배우자 인격 비난 금지**: 갈등지점은 항상 '두 사람 사이 패턴'.
6. **만혼 사주 처리**: 40대 후반 미혼에게 엔진이 뽑은 '인연 강한 시기'가 이미 지난 대운뿐이면 사형선고가 됨. "지난 시기는 언급하되 **반드시 향후 창과 함께**, 향후 창이 약하면 세운 단위로 내려가 찾아라." (이 연령대 미혼 구매자에겐 거의 기본 케이스)

### 기혼 트랙 약속 범위 (가장 약한 고리)
배우자 사주 없이 "부부관계의 결"을 약속하면 콜드리딩. → 약속을 **"당신이 관계에 가져오는 것"**으로 정직하게 좁히고, 말미에서 **부부궁합 상품 CTA**로 연결. (3종 파일럿 2호 후보가 사실상 여기서 나옴)

## 7. 에러 처리 · 테스트

- 코인 **멱등성**: 중복 차감 방지(과거 18회 중복충전 사고 기준). 분석 실패 시 **자동 환불**.
- **3-layer 일관성 시뮬 테스트**: 동일 원국에서 메인 result vs 결혼운 검사 값 대조(등급·배우자성·신살).
- **명리 정확성 critic**: 엔진 대조(배우자성·관살혼잡·일지 지장간·타이밍 연도가 실제 원국과 일치하는지). fabrication 0.
- **quality-gate**: 차별화 규칙(개인사주 중복률)·근거 태그 없는 조언 컷·노출금지 신살·여명 안전장치 위반 검출.
- 시니어 가독성 검수(큰 개념·직관어).
