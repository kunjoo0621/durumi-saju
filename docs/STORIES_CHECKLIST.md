# 사주 매거진(`/stories`) 글 발행 체크리스트

> 글 1편을 추가·수정·머지하기 전 반드시 통과해야 하는 항목.
> 누락된 항목은 PR description에 사유 명시.

---

## 핵심 원칙

**stories의 목적은 트래픽이 아니라 `/menu` 전환**(메뉴에서 사주·궁합·올해운·오늘운 직접 선택).
모든 항목은 이 목적의 도구. 아래 항목 중 SEO·콘텐츠 품질 항목도
"검색에서 만난 사용자를 사주 보기까지 끌고 가는가" 기준으로 평가.

## 1. 전환 가드 (가장 중요 — 매 글 동일 적용)

- [ ] **Floating CTA**: `app/stories/layout.tsx`에 항상 마운트되어 모든 글에서 우하단에 노출. 신규 글에는 별도 작업 불필요 — 레이아웃에서 자동.
- [ ] **Above-the-fold soft CTA**: 본문 페이지 헤더(H1 + excerpt + 메타) 직후 한 줄 텍스트 링크. 스크롤 0%에서 CTA 보이게.
- [ ] **Mid-article CTA (`ctaAfter`)**: 자기진단 모먼트(체크리스트 노출 또는 패턴 공개) **직후** 섹션 인덱스로 설정. 단순 정보 섹션 뒤가 아니라 "내 얘기네"하는 순간 뒤가 정답.
- [ ] **End-of-article CTA**: 본문 끝 카드(자동 렌더). 카피는 글 결말과 자연스럽게 이어지는 한 문장.
- [ ] **CTA 라우팅 일치**: 모든 글의 CTA `href`는 `/menu`로 통일. 메뉴 페이지에서 사용자가 사주·궁합·올해운세·오늘운세 중 직접 선택하도록 한다.
  | 글 주제 | CTA href |
  |---|---|
  | 모든 글 (사주·꿈·궁합·올해운 등) | `/menu` |
  | (구) 세분화된 `/start`·`/yearly/input`·`/battle/input` 라우팅은 폐기 |

- [ ] **CTA tone**: 글 카테고리와 `StoryCTA.tone` 매칭. 컬러는 메인 메뉴(/menu) 카드와 시각 매칭됨.
  - 재물·돈 → `earth` (`#F59E0B`, 메뉴 yearly 카드와 매칭)
  - 연애·궁합 → `love` (`#A855F7`, 메뉴 battle 카드와 매칭)
  - 사주 일반·꿈 → `brand` (`#FF6B6B`, 메뉴 사주 카드와 매칭)

## 2. 콘텐츠 품질

- [ ] **현실 고민으로 시작**: `intro` 첫 문장은 사용자가 자기 얘기로 느낄 일상 문제. "월급은 나쁘지 않은데 통장이 안 채워지면…" 류.
- [ ] **짧은 결론 먼저**: 첫 섹션에서 답을 먼저 준다. ★단 **"결론부터 —" 문구 자체는 쓰지 않는다** — `durumi-blog/harness/lexicon/banned-phrases.txt`에 ban으로 등재돼 있고(매거진 162편 중 159편이 써서 완전 포화), `verify-story.mts`의 M-SLP-01이 막는다. 문구가 아니라 **구조**를 지키라는 항목이다.
- [ ] **체크리스트 ≥ 1개**: `kind: "checklist"` 블록 1개 이상. 사용자 자기진단 도구.
- [ ] **표 또는 콜아웃 ≥ 1개**: `kind: "table"` 또는 `kind: "callout"`. 시각 분리.
- [ ] **사주 용어 노출 최소화**: 첫 등장 시 괄호 안 짧게 풀이. 예: `재성(돈을 상징하는 글자)`. 같은 글 두 번째 등장부터는 풀이 생략. → 메모리 `feedback_durumi_saju_jargon` 참조.
- [ ] **한자 사용 최소화**: 본문 한자 자제. 꼭 필요하면 `충(沖)` 같이 1회 병기. 한자만 단독 노출 금지. → 메모리 `feedback_shorts_no_hanja` 톤 참고.
- [ ] **분량**: **2,500–4,000자** (intro + 모든 sections.blocks 합산). ★검증기(`verify-story.mts` M-LEN-01)는 2,500–5,500자를 통과시키고 그 밖이면 WARN — 이 문서와 `STORY_WRITING_GUIDE.md`가 1,500–3,000 / 2,500–4,000으로 갈려 있던 것을 2026-08-10에 가이드 쪽(2,500–4,000)으로 통일했다. **정본은 검증기다.**
- [ ] **MZ 슬랭 회피**: 35-54세 여성 타깃. 보편적 표현 사용. → 메모리 `feedback_durumi_youtube_audience` 참조.

## 3. SEO 기본

- [ ] **`title`**: ≤30자 (모바일 SERP 노출 임계). 검색 키워드를 자연스럽게 포함.
- [ ] **`excerpt`**: 1문장. SERP description 후보. 검색어 변형 포함.
- [ ] **`keywords`**: 5개 이상. 띄어쓰기 변형 포함 (예: `뱀 꿈 해몽`과 `뱀꿈` 둘 다).
- [ ] **`slug`**: 영문 케밥 케이스 (`snake-dream`, `dombok-saju`). URL 인코딩 이슈 회피.
- [ ] **`publishedAt`·`updatedAt`**: 절대 날짜 (`YYYY-MM-DD`). 발행일·수정일 명확히.
- [ ] **`related`**: 같은 시리즈 또는 인접 시리즈에서 2–3개 슬러그. 내부 링크 자산.
- [ ] **`category`**: `saju` | `dream` | `love` | `celebrity` 중 하나. 시리즈 페이지에서 노출됨.

## 6. 연예인 사주 카테고리 전용 (`category: "celebrity"`)

> 일반 글 항목 1-5 통과는 동일하고, 추가로 아래 항목 전수 통과 필수.
> 부정 단정 어미 1개 누락이 명예훼손 위험으로 직결되므로 grep 자동화 권장.

- [ ] **`celebrity` 필드 채움**: `name` · `birthDate` · `calendar` · `gender` 필수. 시 미상이면 `birthTime` 생략 (사이트 표준 12:00 fallback 작동).
- [ ] **음력/양력 검증**: 위키 데이터가 음력인지 양력인지 한 번 더 확인. 90년대 이후 출생 대부분 양력이지만 일부 농촌 출신은 음력 표기.
- [ ] **생년월일 출처 명시**: `source` 필드에 "위키백과 (YYYY-MM-DD 확인)" 또는 본인 공개 출처 명시.
- [ ] **사주는 사이트 엔진으로 검증 (외부 분석 그대로 옮기지 말 것)**: 임시 데이터 등록 → dev `/stories/{slug}` 페이지의 SajuChart 출력(4기둥·십성·12운성·신살)을 사실 베이스로 사용. 외부 사이트가 말한 격국(염상격 등)·신살(천을·월덕 등)이 **우리 엔진에 안 잡히면 본문에 쓰지 말 것**. 외부 분석은 톤·메타포 참고만.
  - 신살은 **일반 신살 / 12신살** 산출 방식이 다름 — 엔진이 어느 쪽에서 잡았는지 구분해 표기 (예: 화개살은 일반 신살이 아니라 12신살에서 잡힘. "일반 신살로는 ~, 12신살로는 ~"처럼 분리).
  - 흉살을 빼고 길신만 골라 소개할 때 **"핵심 신살은"·"잡히는 신살은" 식 단정 금지** (전부인 것처럼 오해 + 누락감). → **"강점으로 보기 좋은 신살은"**처럼 선별했음을 드러낼 것.
  - 십성 **숫자 카운트 단정 금지** (시 미상이면 시주 마스킹돼 정확 카운트 불가). "비견·겁재가 강하게 드러난다" 식 정성 표현.
  - 12운성 자리(록궁·제왕 등)는 엔진 출력 그대로 (임의 명리 지식으로 단정 금지 — 정화 양인 없음 등 음간 규칙 주의).
- [ ] **인물 활동 이력 cross-check (사주와 별개로 필수)**: 순위·데뷔·수상·소속 등 **사실 정보는 위키백과·KProfiles·나무위키 2곳 이상**에서 확인. 사주는 맞아도 "오디션 1위(실제 2위)" 같은 사실 오류 하나가 팬덤 신뢰를 크게 깎음. 본문에 등장하는 모든 사실 주장(순위·기록·활동)은 출처 확인.
- [ ] **멤버 포지션 단정 주의**: "메인보컬·메인댄서·리더" 등 포지션은 공개 프로필마다 다르게 잡힘. 확정적인 것(센터 등)만 쓰고, 애매하면 "보컬 멤버"처럼 일반 표현. (사주 풀이엔 포지션 정확도가 핵심이 아니므로 무리하게 특정하지 말 것)
- [ ] **가족·지인 언급 시 동명이인 주의**: 가족이 유명인과 동명이인일 수 있음 (예: 앤톤 어머니 "심혜진" ≠ 대중이 아는 배우 심혜진). 유명한 핵심 인물(부모 중 한 명) 중심으로 쓰고, 혼동 위험 있는 가족 언급은 빼거나 낮춰 표기.
- [ ] **부정 단정 어미 금지 (자동 grep 권장)**: 다음 패턴 본문에 등장 시 위험.
  - "결혼이 어렵습니다", "결혼운이 안 좋아요"
  - "건강이 나쁩니다", "단명할 사주"
  - "사기꾼 사주", "망할 사주"
  - "안 됩니다", "할 수 없습니다" 류 단정형 어미
  - → 모두 **"~한 결입니다", "~할 수 있어요", "~조심하시면 좋아요"** 류 완곡으로 전환.
- [ ] **`/dict` 정합성**: 본문에 등장한 사주 용어(재성·일간·도화살 등)의 풀이가 `/dict` 항목 정의와 결 일치.
- [ ] **사진 정책**: 인터넷 프로필 사진 무단 사용 금지. 옵션 = (a) 위키미디어 CC + 출처·라이선스 표기, (b) AI 캐리커처(통일 스타일), (c) 타이포 hero. (a) 또는 (b) 권장.
- [ ] **면책 문구**: 차트 카드 하단에 자동 노출 ("공개된 생년월일을 바탕으로 한 명리학적 풀이이며, 본인의 실제 사주와 다를 수 있습니다."). `source` 필드 있어야 자동 렌더.
- [ ] **삭제 요청 응대 정책**: 본인·소속사 요청 시 24시간 내 글 비공개. 응대 채널 (Naver 폼·이메일) 사이트 footer에 노출 확인.

### CTA 매핑 (연예인 카테고리 한정)

모든 글의 CTA `href`는 `/menu` 통일 (1번 섹션 규칙). 글 결에 따라 라벨만 다르게.

| 글 결 | 라벨 예시 |
|---|---|
| 일주·격국·인물 결 분석 | "{이름}과 비슷한 결의 내 사주 보기" |
| 그 인물의 올해 흐름·운세 | "올해 내 운의 흐름 보기" |
| 다른 인물과의 궁합 | "내 사주와 {이름}의 궁합 보기" |

## 7. 발행 전 critic (독립 세션 · 필수)

> 기계 하네스(`verify-story.mts`)가 통과시켜도 여기서 걸리는 게 매 배치 나온다.
> 기계는 형식을, critic은 **판단**을 본다. 작성자 본인이 하지 않는다.

### 규격
- **글당 1회 개별 실행.** 여러 편을 한 번에 몰면 한 편만 지적하고 끝난다(실측).
- ★**형제 대조 목록에 "주제가 가까운 글"만 넣지 말 것.** 2026-08-10 rain-dream 사고 —
  지정한 9편(물 계열)은 전부 무혐의였고 정작 범인은 목록 밖 bird-dream(4-gram 16.2%)이었다.
  **같은 카테고리 최신 발행순으로도 2~3편 반드시 포함**한다. 기계 쪽은 M-SIB-01이 보지만
  섹션 골격·논리 비트는 여전히 critic 몫이다.
- ★**critic이 제시한 "새 각도"를 그대로 채우면 창작이 난다.** 같은 날 블로그 FAQ에서 실제로 발생했다
  (권고 예시를 반영했더니 소스에 없는 판독 규칙 2개 생성). **차별화는 통사·프레이밍으로만 만들고,
  전승 귀속 어미가 붙는 문장은 예외 없이 소스나 사전의 특정 문장으로 역추적돼야 한다.**
- ★**본문을 고쳤으면 그 절의 figure를 반드시 같이 연다.** 2026-08-10에 본문에서 지운 클론 문장이
  fig2·fig3 PNG에 살아남아 두 번 잡혔다. 렌더 자산은 텍스트 수정을 따라오지 않는다.
- **작성자의 docstring·주석·자가보고를 근거로 인용 금지.** "디클론 완료" 같은 자가 선언은 여러 번 틀렸다.
- 입력 3종: 글 전문 + 검증기 리포트 + 사전 원문(`lib/dict/data/`).

### 7-1. 명리 정확성 [상]
1. **엔진값 전수 대조** — 4기둥·오행·십성·12운성·강약·신살. `computeCelebritySaju` 산출값과 1:1.
2. **신살 dual-field** — `shinsal.matches`(일반)와 `pillar12Shinsal`(12신살)을 **둘 다** 본다. 한 필드만 보고 단정 금지. 같은 칸이 두 체계에 겹쳐 잡히면 그 사실을 글이 밝혔는지 확인(안 밝히면 개수 부풀림으로 읽힌다).
3. **오행 상생상극 방향** / **십성↔신살 혼동** / **십성 의미 왜곡**.
4. **성별 매핑** — 여자=관성이 배우자 별, 남자=재성. 뒤집히면 [상].
5. **시 미상** — 득시는 시주가 없으면 **판정 자체가 불가**다. "네 항목 모두 미해당"식 서술은 내부 모순.
6. **사전에 근거 없는 명리 주장은 그 자체로 [상]**(창작 의심). 조견표·수치·통계는 사전 원문 그대로만.
7. **사전이 틀렸을 수 있다** — 글이 사전을 성실히 옮겨도 사전 쪽 오류면 결과는 오류다. 형제글과 정의가 어긋나면 어느 쪽이 맞는지 판정하고 사전까지 고친다. (2026-07-31 실측: 관살혼잡·목욕=도화 2건)

### 7-2. 글 정확성 [상]
- 이력·수상·순위·시청률을 **1차 출처로 표본 검증**. 두 개의 다른 사실을 한 문장에 합치지 않았는지(최종회 시청률 ≠ 자체 최고).
- 글 내부 모순(앞에서 A, 뒤에서 not A), excerpt↔본문 충돌, 숫자 불일치.
- **연예인**: 타 연예인 실명·비교 0(같은 작품 출연자·같은 그룹 멤버 포함). 미성년·10대는 연애·결혼·궁합 서술 배제, 일지를 "배우자 자리"로 호명하지 않음.
- 부정 단정 어미·예언형 서술·"무료" 0.

### 7-3. 풍성함(정보이득) [중]
- **이 글에만 있는 값어치를 최소 1개 지목**한다. 못 하면 그 자체가 결함이다.
- **자기잠식** — 기존 글과 검색 의도가 겹치는지. 겹치면 각도를 분리하고 상호 링크로 동선을 만든다.
- **형제 클론** — 기계는 문장 단위만 잡는다. critic은 **논리 비트·문형 골격**을 본다. 상습 슬롯: 오프너 · 마무리 · 체크리스트 도입/마감 caption · 각주 disclaimer · FAQ 답 · 중간 CTA · 하단 card.
- ★**같은 날 같은 지시로 쓴 글끼리의 교차복제**가 최대 리스크다. 원본 대조(dup_check)로는 원리상 안 잡힌다.
- ★**디클론은 대상을 지정하면 다른 형제로 옮겨 간다.** [상] 수정 후 재검 critic을 반드시 한 번 더 돌린다(2026-07-31 실측).

### 7-4. 카드(figure)
- 렌더 PNG를 **사람이 직접 열어 본다.** 린트는 깨짐을, 사람은 어색함을 잡는다.
- 실측 사례: `.fill`이 인라인 span이라 `height:100%`가 안 먹어 **오행 막대가 통째로 비어 렌더**됐는데 린트는 통과했다(2026-07-31, 라이브 배포분에서 발견).
- 카드가 본문보다 더 많이 주장하지 않는지(카드에만 있는 명제는 본문으로 올린다).
