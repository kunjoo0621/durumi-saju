# 리포트 결함 건의함 (셀프 건의함)

**운영 방식 (운영자 지시 2026-08-10)**
발견 즉시 고치지 않는다. **결함을 여기 모아 실측 증거를 쌓은 뒤, 한 번에 확실하게 고친다.**

왜: 품질 사이클마다 1~2건씩 즉흥 수정하면 (a) 표본이 작아 진짜 빈도를 모른 채 고치고
(b) 수정이 또 다른 오탐·비문을 낳고(3·5차에서 실제 발생) (c) 배포 횟수만 늘어난다.
증거가 쌓이면 빈도·심각도로 우선순위를 정할 수 있고, 결정론 수정은 묶어서 한 번에 검증·배포할 수 있다.

**규칙**
1. 새 결함은 **실측 근거(리포트 식별자·출고문 원문·재계산값)** 와 함께 아래 표에 추가한다. 추정만으로 등재 금지.
2. 이미 있는 항목을 다시 만나면 **목격 건수만 갱신**한다(빈도가 우선순위다).
3. 상태는 `누적중` → `수정대기(증거충분)` → `수정중` → `배포완료`.
4. 착수는 **운영자 승인 후**. 결정론 수정은 묶어서 한 브랜치, 프롬프트 수정은 실 Gemini 재생성 검증이 선행.
5. 사이클을 돌 때마다 이 파일부터 열고, 기존 항목이 재발했는지 먼저 센다.
