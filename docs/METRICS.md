# 지표 읽는 법 — 무엇을 세고, 무엇이 아닌가

**이 문서의 존재 이유:** 2026-08-20~21 이틀간 마케팅 분석을 하면서 **같은 방식으로 8번 틀렸다.**
전부 한 가지 패턴이다 — **도구가 준 숫자를 액면가로 읽고 원본을 확인하지 않았다.**

| 주장 | 실제 | 원인 |
|---|---|---|
| "두루미 후기 1,919건" | **0건** | 네이버 `total` 이 토큰을 쪼개 OR 로 긁음 |
| "사전 CTA 가 병목(3,404→819)" | **정반대. 사전이 가입 54%·매출 44%** | Vercel 페이지뷰를 퍼널로 읽음 |
| "빈 구 소재를 정리하자" | **제목 13개짜리 주력 반응형 소재** | `ad.headline` 만 읽음 |
| "일간·일주 사전이 없다" | **238개 다 있음** | 커버 목록을 하드코딩 |
| "공유 보상을 만들자" | **이미 구현됨(종류당 5알)** | 코드 확인 안 함 |
| "GSC 를 붙이자" | **키가 6/5부터 있었음** | 파일 확인 안 함 |
| "footer 접힘이 보류 사유" | **사전점검 6항목 전부 통과** | 메모 오독 |
| "developers.naver.com 에서 발급" | **2026-07-31 신규 신청 종료** | 최신 확인 안 함 |

숫자가 틀린 게 아니다. **그 숫자가 무엇을 세는지 확인하지 않은 게 틀렸다.**

---

## 원칙 셋

1. **지표는 대리값이다.** 보고하기 전에 "이 숫자가 정확히 무엇을 세는가"를 답할 수 있어야 한다.
2. **"없다/안 되어 있다"고 말하기 전에 반드시 찾아본다.** 코드·DB·문서·파일.
   이번에 "없다"고 한 것 중 절반이 이미 있었다.
3. **원본을 표본으로 열어본다.** 집계값이 이상하지 않아 보여도, 상위 10건은 열어본다.
   `두루미사주 total=1,919` 는 전혀 이상해 보이지 않았지만 내용은 오겹살집이었다.

## 도구별 — 이 숫자는 무엇이 아닌가

### `scripts/vercel-analytics.mts` — Vercel Web Analytics

| 지표 | 무엇인가 | **무엇이 아닌가** |
|---|---|---|
| 페이지별 방문자 | 그 경로를 본 순 방문자 | **퍼널이 아니다.** 한 사람이 A·B 를 다 보면 양쪽에 계산된다. "A 3,404 → B 819" 는 전환율이 아니다 |
| 유입처(referrer) | 직전 페이지 도메인 | 앱 내 이동·유튜브 앱은 `direct/none` 으로 섞인다 |
| UTM 차원 | — | **Enterprise 플랜 전용.** 지금 조회 불가 |

**퍼널을 보려면 DB `users.landing_path` 를 써라** → `scripts/channel-roi.mts`. 그게 정답이다.

### `scripts/naver-demand.mts` — 네이버 검색 API

| 지표 | 무엇인가 | **무엇이 아닌가** |
|---|---|---|
| `total` | **상한(upper bound)** | 그 검색어를 다룬 문서 수가 **아니다**. 네이버는 토큰을 쪼개 OR 로 긁고 **쿼리의 따옴표도 무시**한다 |

**규칙: 적중률 30% 미만이면 `total` 을 인용하지 말 것.**
스크립트가 상위 100건을 실제로 열어 적중률을 재고 `← total 신뢰불가` 를 붙인다.

실측(2026-08-21):

| 브랜드 | total | 적중률 | 실질 |
|---|---:|---:|---:|
| 두루미사주 | 1,919 | **6%** | 115 (그중 자사글 9%) |
| 사주아이 | 544,427 | **100%** | 544,427 |
| 점신 | 21,072 | 91% | 19,176 |

같은 API·같은 필드인데 하나는 쓰레기고 하나는 진짜다. **표본을 안 열면 구분이 안 된다.**

### `scripts/naver-ad-stats.mts` · `naver-kw-stats.mts` — 네이버 검색광고

- **소재는 두 종류다.** 단일(`TEXT_45`)은 `ad.headline`/`ad.description`,
  **반응형(`RSA_AD`)은 `assets[]` 에 `linkType=HEADLINE/DESCRIPTION`** 으로 들어간다.
  `ad.headline` 만 읽으면 RSA 가 빈 소재로 보인다.
- **랜딩의 utm 은 의미가 없다.** 네이버가 쿼리스트링을 `NaPm` 으로 통째로 바꿔치기한다.
  유입 추적은 `middleware.ts` 의 NaPm 파싱이 한다. (`lib/naver-ad-params.ts` 주석 참조)
- **전환수(`ccnt`)** 는 네이버 쪽 전환추적 설정·검수가 끝나야 찍힌다. 스크립트가 깔려 있어도 0 일 수 있다.

### `scripts/gsc-queries.mts` — Google Search Console

- **데이터가 2~3일 지연**된다. 어제 데이터는 없다.
- **90일치만 보관**한다. 장기 추이는 주기 수집으로 직접 쌓아야 한다.
- 속성이 **도메인형**이라 `siteUrl` 이 `sc-domain:durumisaju.com` 이다.
- 서비스 계정 권한이 없으면 **403 이 아니라 `sites.list` 가 빈 배열**을 준다.

### `scripts/live-dashboard.mts` · `channel-roi.mts` — Supabase

- **Supabase select 는 기본 1000행에서 잘린다.** 집계·감사는 반드시 페이지네이션.
  (과거에 이걸로 10배를 오판한 적이 있다)
- `channel-roi` 의 코호트는 **가입일 기준**이고 그들의 **전체 결제**를 합산한다.
  창이 짧으면 아직 안 낸 돈이 빠져 LTV 가 낮게 나온다 → **30일 값을 기준으로 본다.**
- `users` 의 빈 컬럼은 "미입력"이 아니다. 분석 정보는 `saju_results` 에 있다.

### `~/projects/durumi-yt-stats/` — YouTube Data API

- **노출수·CTR 은 API 가 안 준다** (스튜디오 전용). 썸네일 테스트는 스크린샷으로.
- `EXT_URL` = 외부 링크 클릭. 쇼츠는 원래 낮지만 **28일 4회면 링크가 없거나 안 보이는 것**이다.

## 주장하기 전 체크리스트

무언가를 **"없다 / 안 된다 / 병목이다"** 라고 말하기 직전에:

- [ ] **있는지 찾아봤나?** — `grep -rn` 으로 코드, DB 조회, `docs/API_INVENTORY.md`, 파일 존재
- [ ] **이 숫자가 정확히 뭘 세는가?** — 위 표에서 해당 도구의 "무엇이 아닌가" 확인
- [ ] **원본 표본을 열어봤나?** — 상위 10건이 정말 내가 생각한 그것인가
- [ ] **더 정확한 출처가 있나?** — 페이지뷰 대신 DB, 추정 대신 실측
- [ ] **최신인가?** — 외부 서비스 정책은 바뀐다 (네이버 오픈API 가 하루 만에 뒤집혔다)

**쓰기(등록·수정·삭제) API 를 호출한 뒤에는 반드시 재조회로 검증한다.**
2026-08-21 네이버 키워드 등록이 `200 OK` 에 키워드까지 에코백했는데 **실제로는 하나도 안 들어갔다**
(`bidAmt` 누락 시 조용히 무시). 재조회 안 했으면 "등록 완료"라고 거짓 보고할 뻔했다.
